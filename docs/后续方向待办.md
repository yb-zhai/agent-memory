# 后续方向待办

按「做」与「暂缓」分开记录，附各自的前置条件。来源：早期战略讨论（MCP 后继 / 多库路由 / Hindsight 方案）。

## 已完成

- **MCP A/B 类**：npm 包 `nebula-memory-mcp` + 官方 MCP Registry（OIDC Actions 自动发布）。
- **Hindsight 借势对接**：README 已写明兼容 vectorize-io/hindsight，用户自行安装。
- **多库路由 · 轻量 namespace**：`remember`/`recall`/`stats`/`forget` 增加可选 `namespace` 参数；不传=原单库（完全兼容），传了=独立子库 `DATA_DIR/__ns__/<name>`。npm 1.1.0 / server 1.4.0。

## 暂缓（C/D 类）——等用户规模/真实需求上来再评估

| 方向 | 所属讨论 | 暂缓理由 | 重启前置条件 |
|---|---|---|---|
| Python MCP（FastMCP 版） | MCP 后继 C 类 | 现有 Node 版零依赖、npx 一键已够用；重写一遍收益不明 | 有明确的 Python 用户诉求，或出现 Node 版覆盖不了的场景 |
| 远程 / SSE MCP 云服务 | MCP 后继 D 类 | 要服务器 + 运维 + 成本，和「纯本地零花钱」定位冲突 | 有付费用户 / 多端同步刚需，且愿意承担运维 |
| Hindsight 一键安装脚本 | Hindsight 方案 B 类 | 上游安装本身有依赖，维护脚本有持续成本 | 多名用户反馈「装不上」 |
| Hindsight 增强发行版（fork） | Hindsight 方案 C 类 | 和 44k⭐ 上游冲突，风险高 | 明确要产出差异化 fork 且处理好上游关系 |
| Hindsight 云服务 | Hindsight 方案 D 类 | 大工程，另一产品形态 | 独立商业模式验证 |

## 判断原则

这些不是「不做」，是「现在投入产出不划算」。触发评估的信号：真实用户反复提出同类需求、星标/使用量上一个台阶、或出现能显著降低维护成本的现成工具。届时再针对单项出详细方案。
